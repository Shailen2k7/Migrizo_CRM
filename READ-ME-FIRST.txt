MIGRIZO CRM — WHATSAPP DIAGNOSTICS + PERFORMANCE
=================================================

WHAT THIS FIXES
---------------
0. Secret mismatch tolerance. The webhook now trims whitespace off the
   Netlify value (a trailing newline on paste is the #1 cause of 401s)
   and repairs secrets mangled by the URL, e.g. a "+" that arrives as a
   space. When it still does not match, the log records the LENGTH and
   first/last two characters of both sides so you can see the
   difference without ever exposing the key.
1. You could not tell WHY inbound WhatsApp messages were not arriving.
   Now the system tells you, in one sentence.
2. The inbox felt slow and the connection pill said "Not connected"
   for several seconds before snapping to your number.
   Both causes are fixed.

--------------------------
STEP 1 — Drag these two folders into the root of your GitHub repo.

STEP 2 — In Supabase → SQL Editor, paste and run:
           supabase/migrations/042_whatsapp_webhook_log.sql

STEP 3 — Let Netlify finish deploying.

STEP 4 — Open this in a browser tab while logged into the CRM:
           https://<your-domain>/api/whatsapp/diagnose

         Read the "next_action" field at the top. That is your answer.


WHAT THE DIAGNOSTIC TELLS YOU
-----------------------------
It checks the chain in order and reports the FIRST broken link:

  env       Are INTERAKT_API_KEY and WHATSAPP_WEBHOOK_SECRET actually
            on this deploy? (Reports set/not-set and length only.
            Never the value.)
  settings  Is there a settings row, is your number saved, is it
            connected, is dry_run still on?
  inbound   Has Interakt EVER called your webhook? This is the one
            that matters right now. Four possible verdicts:

              NO_CALLS      Interakt has never reached the URL.
                            Wrong URL, or the message-event
                            checkboxes are not ticked in Interakt.
              ALL_REJECTED  Interakt is calling but every call is a
                            401. The secret in the ?key= does not
                            match Netlify.
              NO_INBOUND    Interakt is calling and authenticating,
                            but has never sent a message_received
                            event. The inbound checkbox is off.
              HEALTHY       Inbound is arriving and being recorded.

  templates How many templates exist and how many Meta has approved.
  traffic   Messages in/out/failed, and — importantly — whether any
            conversations landed under a DIFFERENT workspace_id than
            the one you log into. Those are invisible to you and no
            normal query would ever surface them.


THE WEBHOOK LOG
---------------
Migration 042 adds whatsapp_webhook_log. Every request that hits the
webhook is now recorded there — including the ones rejected with 401
and the ones that error — with the raw Interakt payload.

Read it directly any time:

  select received_at, event_type, outcome, detail, phone
    from whatsapp_webhook_log
   order by received_at desc
   limit 30;

Outcomes: unauthorized | bad_json | handled | ignored | error

The log auto-limits itself to 14 days via whatsapp_webhook_log_prune().
Reads are campaign-admin only — it contains phone numbers and message
text.

Important: the webhook still works fine if you deploy the code before
running the migration. The log insert fails silently in that case;
message handling is unaffected.


PERFORMANCE CHANGES
-------------------
1. Load waterfall removed.
   The page used to await templates+settings, THEN await
   conversations+stats — two full round trips before showing real
   data. That is why the pill sat on "Not connected". Now all four
   requests go out together.

2. Idle clock stopped.
   A setState fired every second, forever, re-rendering the whole
   page including every list row and the open thread — even on an
   empty inbox. Now the clock only runs when a 24-hour window is
   actually counting down, and only ticks per second when seconds
   are visible on screen (under one hour left); otherwise every 30
   seconds.

     Idle re-renders per 10 min, empty inbox:      600  ->  0
     Idle re-renders per 10 min, one 10h window:   600  ->  20

3. Websocket no longer rebuilt on every click.
   Selecting a conversation used to tear down the realtime channel
   and open a new one. Events landing during the swap were lost.
   The channel is now created once per page.

4. Delivery receipts coalesced.
   A burst of receipts fired two queries per receipt — sending to 50
   leads meant ~100 round trips in a few seconds and a visibly
   thrashing list. Now one refresh per 250ms.

5. Optimistic send — the Send button no longer makes you wait.
   Before: you watched four sequential round trips before the box
   even cleared. POST -> API route (plus possible Netlify cold
   start) -> DB insert -> Interakt HTTP call -> response, THEN a
   full 400-row thread refetch, THEN a conversation refresh, THEN
   a stats refresh. All of it in front of you.

   Now the bubble appears the instant you hit Send and the box
   clears immediately. The network work happens behind you and only
   the tick state waits on the server — which is what WhatsApp
   itself does. The Send button is no longer disabled mid-flight,
   so you can keep typing the next line.

   Reconciliation is race-safe: if the realtime channel delivers
   the real row before our own POST response returns, the
   placeholder is replaced rather than duplicated. A failed send
   marks the bubble red AND puts your text back in the box, so it
   can never silently eat what you typed. 9/9 unit tests cover
   these races, including a lead replying with the same word you
   just sent.

6. The UI stops lying.
   - The pill shows "Checking..." while settings load, instead of
     "Not connected".
   - A failed query now renders a red error box with the actual
     message, a Try again button, and a link to the diagnostic —
     instead of "No conversations yet", which sends you looking in
     the wrong place.
   - The spinner can no longer spin forever: the loading flag is
     cleared in a finally block.

WHAT IS STILL OUTSTANDING
-------------------------
- Turn OFF Interakt's built-in auto-reply. That "Welcome to Migrizo"
  message was sent by Interakt, not by your CRM. It will never appear
  in your inbox, it burns the 24-hour window before your team sees
  the lead, and it means the customer's phone and your CRM
  permanently disagree.
- Submit your 11 templates in Interakt for Meta approval.
- TURN OFF DRY RUN. This is why your messages are not reaching
  anyone right now:
      update whatsapp_settings set dry_run = false;
  Dry-run logs the message and deliberately never calls Interakt.
  The amber line under the composer says so.
- There is still no "New conversation" button. Cold outbound is
  blocked by Meta until templates are approved, so that screen is
  the next build once approval lands.
